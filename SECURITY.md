# Security

Scope: the Overhear MCP server exposed on a network, the simulated device host in front of it and the
AWS account behind it in cloud mode. This file lists the attackers we design against, the attack we
expect from each, the defence that holds, the file that holds it and the test that proves it. A row
with no automated test says so plainly. Attack ids S-1 to S-12 are defined here and used nowhere else.

## Attackers

| Id  | Who                                      | What they want                                               |
| --- | ---------------------------------------- | ------------------------------------------------------------ |
| A1  | Anonymous caller who finds the endpoint  | free model inference on our AWS bill                         |
| A2  | Malicious web page in the user's browser | drive a local server through the browser (DNS rebinding)     |
| A3  | Author of a source URL or document       | SSRF, prompt injection, resource exhaustion                  |
| A4  | A second legitimate principal            | read or edit another principal's episodes, tasks or sessions |
| A5  | Network observer or log reader           | lift a token or a media URL                                  |

Every ceiling lives in one module, `packages/core/src/ceilings.ts`. Runtime code and tests import the
constant, never a literal. A hostile input cannot exhaust memory or CPU past these bounds.

| ------------------------------------------------- | ---------------------- | ----------------------------------- |
| `MAX_SOURCE_CHARS`                                | 50000                  | source text kept after extraction   |

| `MAX_REDIRECTS`                                   | 3                      | redirect hops, each re-checked      |

| `MAX_PARTS`                                       | 8                      | parts per episode                   |

## What is real and what is simulated

- The Alexa+ device is simulated. The device host and the web client stand in for the Alexa+ surface
  so the full flow runs without Alexa hardware. Everything they call is the real server.
- Real: the MCP server and its Streamable HTTP transport, the seven tools, the SQLite durable stores,
  the ffmpeg audio mixer and the SSRF-guarded source fetcher. In AWS mode the Bedrock models, the Polly
  voices, S3 storage and the DynamoDB stores are the real services.
- Mock mode is labeled. `OVERHEAR_MODELS=mock` swaps in deterministic model and voice twins. `GET
/health` reports the models mode and the store mode. The startup banner prints both switches, so the
  run mode is never ambiguous in a log or a demo. The default release gate runs mock models plus
  local store, so it spends no money and needs no AWS keys.

## Known limits

Stated plainly, not hidden.

- No OAuth 2.1 authorization. The server uses static bearer tokens only, not the 2025-11-25 MCP
  authorization flow. A token is a long-lived shared secret until it is rotated in the token file.
- Rate limits are in-process. One process holds the counters, so two or more replicas behind a load
  balancer would each enforce their own budget. A shared limiter is needed for a multi-replica
  deployment.
- The AWS-mode DynamoDB event store shares one standalone GET-stream id across sessions, so SSE
  resumption on that stream is not cleanly per-session there. Local mode gives each session its own
  event store, so local mode is the correct resumable path.
- Prompt-injection defence is containment, not detection. Output is schema-validated and no tool has a
  side effect beyond generating audio, but the server does not try to spot an injection attempt in the
  source itself.
- Generated audio may contain model errors about the source. The episode carries no per-line fact
  check. The `ask` tool flags an answer as ungrounded when neither the source nor the transcript
  supports it, but the narration itself is not verified line by line.

## Run the gate

One command runs every check above in order and prints `ALL GREEN` only when all of them pass. CI runs
the same script, so a reviewer gets the same verdict.

```
./verify.sh
```
